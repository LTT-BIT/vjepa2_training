# 新独立录制：采集与一次性离线评价

正式锁：`configs/tomato_frozen_independent_20261112/b0.lock.v3.json`。代表模型固定B0 seed42，seed43/44只作稳定性复验，不从新数据挑最好种子。Future1.5秒、2Hz、Future0.5/K2、Current0.8/K2、七阶段顺序、事件和Prompt评分均冻结。新集合不进入训练、修正器、阈值、持续时间先验或选模。

## 采集建议

建议先采16～20条新的完整七阶段录制，跨至少两个新采集时段；这是实用试点规模，不保证统计精度。不要从旧包抽Episode、更名复制或把已用于研究的10条重新叫盲测。

|条件|建议录制|要区分的问题|
|---|---:|---|
|完整七阶段，正常速度|4|普通输入分布下的全链路基准|
|慢/快及途中变速|4|固定1.5秒预测是否依赖操作速度捷径|
|较长adjust及pickup_2前可见停顿|4|可见动作先兆与操作者选择启动时机能否区分|
|真实连续操作中的停顿、姿态变化、轻度自然遮挡|4～8|Current证据、观测完整性与阶段历史的作用|

不为8个旧验证转换定制动作规则。特别保留adjust→pickup前后的连续观察；当姿态相似而启动等待不同，才能判断未来时刻是否存在稳定可观测先兆。相机角色在采集记录中写清，不能默认某个cam一定是右腕。

沿用已有清晰Subtask标准，为新录制保留正常发布的原标注；不重标旧100条，不恢复8770的128项结果补标。主评价集合预先限定normal、30Hz、三路RGB、双FR3+双Sharpa、完整连续七段且reviewed。中途失败或不完整录制保留原件并单独登记；不能在看完分数后静默剔除难例。当前入口对整个catalog全部通过才启动评分，不自动丢掉个别失败项。

## 输入清单和一条命令

按`configs/tomato_frozen_independent_20261112/catalog.example.json`制作自己的catalog，填真实绝对路径、`meta/episodes.jsonl`中的source_recording_id和既有发布Subtask路径，记录实际采集条件。示例含占位符，不能直接当作数据运行。

```bash
cd /home/user/vjepa2_training
.venv-tomato/bin/python -m tools.run_tomato_frozen_evaluation \
  --index /ABSOLUTE/PATH/TO/new_catalog.json \
  --out runs/tomato/new_independent_COLLECTION_ID
```

只检查输入可先加`--validate-only`并使用另一个新输出目录。正式评价不提供训练或阈值搜索入口；登记后即占用其身份，输出目录不覆盖。全局登记在`runs/tomato/frozen_independent_registry_v1`，真实集合不能切换到空登记目录绕过重用检查。失败评价保留现场和登记，不自动释放成“未见数据”；当前版本不自动续跑。

工具实际检查：

- 模型、归一化身份、代码、旧数据和标注哈希；冻结的100条仍84/8/8。
- 旧100及其他历史暴露录制的source ID和Parquet/视频SHA256；当前封存104个source ID、416个内容哈希，包含已剔除历史样本。
- 同集合和跨集合重复内容、被更名的旧录制、当前原始目录与输出目录隔离。
- 已发布非draft/non-inherited Subtask、源文件绑定、七阶段完整覆盖、无伪造缺失段。
- 精确关节名称/顺序、30Hz状态时间轴、三路视频逐帧完整解码及PTS对齐。
- 原B0的训练归一化只读；新集合仅提特征、推理、评分和记录，原始文件不改。

哈希不能识别所有重编码衍生物，也不能替代采集来源的真实声明。角色约束是本工具的流程协议，不能阻止人在别处手工训练；任何改用途都会取消该集合的独立评价资格，必须另留未接触的新录制。

## 输出及判读

每个种子保存：原始Current/Future概率、参考观测时间戳、七阶段状态、Prompt版本/事件时间线、逐Episode的JSON与中文Markdown、Future严格事件、七阶段混淆矩阵、Prompt早/按时/晚/缺失、状态不一致及潜在后续失配、重复阶段统计、Memory事件日志与最终快照。所有结果同时报告，不以新集合最高F1重新选模型。

时间线中的arrival时间是离线调度模拟值，不是现场网络测量。达到return_stem只代表决策序列到了最后位置；这些录像即使有明确完成标注，本次也未运行新Agent驱动的VLA，不能据回放计算闭环实机成功率。

所有六个真实转换均按冻结规则计分。Future首次稳定类别只初始化、不算一次转换预警；极短阶段或起始阶段可出现预警窗口不足两次新观测的情况。保留阶段长度、时间网格和原分母来解释这些结构性限制，不在看结果后剔除短阶段或改匹配窗口。

## 为以后区分瓶颈保留什么

除三路视频、完整原始关节状态和Subtask外，保留source原始时间戳及采集条件。真正授权闭环试验时，再同时记录观测、Agent请求/完成/到达、Prompt确认、VLA请求/完成、Chunk版本、控制器接受/拒绝及应用起止时间和命令/实测轨迹。当前不连接机器人。

若新录制中Current也持续分错，再研究视觉/状态表征；若Current可靠而Future只在不可预测停顿中错位，先研究事件监督与不确定性表达；若模型证据正确但阶段/版本错位，先修接口和决策；若决策正确但新Agent控制下动作失败，再研究VLA执行。只有现有标注和日志确实无法区分某个结果时，才补充那个具体证据，不预设需要新结果验证器或大型长期记忆模型。
