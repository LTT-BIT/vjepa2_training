# Future预警因果平滑：三种子单因素对照

本轮实际实现并回放了一个固定参数的因果概率平滑方案，结果退化，不采用。不重新训练B0，不修改Prompt、OpenPI或RTC。没有证据支持将本方案替换当前独立1.5秒双头研究候选。

## 1秒与1.5秒的含义

1.5秒是既有实验选择的研究预测时距，并非V-JEPA编码器固有参数，也不是Prompt必须提前切换的时间。历史0.5/1.0/1.5秒分类头均实际测试过，参见`docs/TOMATO_TEMPORAL_RESULTS_20261108.md`第146行；历史1秒独立头与Joint对比见第82行。时距改变监督目标和可提前预警范围，因此会影响结果，不宜在修复决策时同时改动。历史不同目标的Macro-F1不能直接比较高低来选时距。

本次对新8条开发验证、三个种子的全部缓存逐项核查：30Hz下未来1.5秒严格对应anchor+45帧，尾部不足45帧的未来标签屏蔽。缓存观测时间等于anchor/fps；人工未来类别只用于评分，无未来画面参与输入。此检查确认当前监督时间映射一致，不能证明全部模型已时间校准。

三个种子都不满足“提高召回且不增加各自误报”的预注册筛选条件。seed42事件Precision从0.740降至0.604，事件F1从0.755降至0.604；中位提前量从0.567秒降至0.500秒。Current和Prompt完全不变。平滑后的概率属于实验决策证据，不是重新训练的Future分类头。

seed42救回`0b12ac0f...`第5次pickup→harvest：原事件在边界前2.767秒，平滑后边界前1.267秒，进入严格窗口。但它丢失的9次原正确事件，其最近同类型候选均落在边界或之后（0～0.4秒）。原预警余量仅0.1～0.5秒，再等待就会跨界。这也解释了为何事件总数可能减少，严格口径误报却增加：迟到预警同样是不匹配事件。

逐事件数据保存在`docs/validation/tomato_causal_filter_20261111/event_comparisons.json`，按seed、录制身份、阶段序号、边界时间列出全部144条配对评分；这只是48个真实事件的三种子重复，不是144个独立事件。`changed_events.json`额外给出救回/丢失事件的最近同类型时间偏移，仅作诊断，未改变匹配。

## 结论与后续

固定概率平滑不能同时纠正过早和过晚证据，拒绝采用；不继续在此8条开发验证上反复搜索平滑常数。该结果支持停止单纯增加等待的修补，不能推出所有时序校准都无效，更不能推出需要重新标注或大型记忆网络。

下一项有动机的训练对照应在训练录制的分组内部划分上，利用现有Subtask学习时间相关证据，先确认过早/过晚是否在未参与拟合的训练组也存在，并与既有失败Time Head配置逐项核对，避免重跑。若要训练小型候选，应预先锁定损失与选择规则，同时评估全部转换的救回、丢失及Prompt时机，再在开发集单次评估。当前没有新候选超过B0，也没有启动新分类头或编码器训练。
