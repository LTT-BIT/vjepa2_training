# 番茄阶段边界复核规范 v1（待人工试标确认）

适用：本轮历史验证录制复核及后续新录制。该规范提出统一的可观察锚点，不声称历史标注采用过同样规则。采用前由两位标注者在开发录制试标、形成共识并锁定版本；不能只给模型错例换定义。本轮原标注、数据版本和40/56主结果保持不变。

## 时间轴与原则

用源视频帧号和真实时间戳记录，不以模型2Hz采样点代替30Hz边界。区间统一为[start_frame,end_frame)，相邻阶段共享同一边界。最终阶段结束于录制结束是行政裁剪点，不等同任务成功。

采用“可见动作事件”标注，不推测操作意图，不以模型概率、关节速度阈值或Prompt切换定义真值。3帧连续可见可作为动作持续性的复核依据，边界回记首帧，而不是第三帧；30Hz约0.1秒。短暂遮挡、动作重叠、镜头外操作均记录最早/最晚合理帧，不强行精确到一帧。

保留辅助锚点：接近开始、手指首次接触、抓握闭合、物体开始随手移动、离盘、返程开始、触盘、松手、调整开始/结束。这些锚点允许区分“接近/抓取/离盘”几种定义；它们不是新增在线模型输入。

## 四类开始、结束与反例

|阶段|统一主边界锚点（审议稿）|结束条件|重要反例和歧义|
|---|---|---|---|
|pickup 拿起|右手开始一次新的拿起抓握序列：可见手指从盘内推拨/重定位转为围拢、接触或闭合抓持的首帧；单纯接近不够。后续物体随手移动用于确认抓握关联，不能把成功离盘时刻当作默认开始。|下一次harvest开始；拿起后等待和持稳仍归pickup。|明确的新抓握尝试即使失败也归pickup尝试，不能只标成功动作；随后回到adjust要保留真实回退序列。调整时短暂抬动、接近后撤但没有可辨新抓握时，记录歧义和辅助锚点，不能预设其为pickup或负例。|
|harvest 摘取|右手持稳物体后，左手/工具开始一次针对果实的可见摘取接近动作的首帧；后续接触/分离用于确认该接近属于摘取，边界回记接近开始。|右手开始真正return返程。|失败摘取、重复摘取、往左篮放果和阶段内停顿仍属harvest；不能每次剪取都新增同名阶段边界。空梗不自动等于已开始return。|
|return 放回|右手持物体/裸梗开始面向右盘的连续返程运动首帧。开始返程是边界，不是触盘/松手时刻。|return→adjust时，由adjust开始的首帧结束；最终return到录制结束，另记触盘/释放锚点。|临时下移、短暂接近盘后继续harvest，不按成功返程处理；真实回退序列须单独记录，不能强制塞入标准七阶段。|
|adjust 调整|物体已经由盘支撑后，右手指首次为盘内重新定位/改变朝向进行可见操作的首帧；若与松手重叠，标区间。|下一次明确新拿起抓握序列的主锚点；调整后静止和单纯接近仍在adjust。若已开始新的拿起闭合，即使暂未带动物体也可进入pickup尝试，须与继续盘内重定位区分。|抬起再调整、重复闭合、握住等待均易与pickup混淆；须结合抓握序列和后续物体运动判断是否新拿起尝试，不能仅凭静态握姿或机械臂开始接近判定。|

上述pickup规则明确选择“新的拿起抓握序列开始”，不选择“成功离盘才开始”。边界是动作起点，不能以成功与否决定是否出现过尝试。调整闭合与拿起闭合无法视觉区分时，用最早合理新抓握到最晚明确抓持/带动物体之间的区间表达不确定性，不能按模型时刻选点。现有提前1.3秒Prompt样本必须同时复核闭合、带动物体、离盘三个锚点。可观察阶段开始与机器人何时获准发出下一条动作指令是不同问题，本轮不据此修改控制逻辑。

## 七个有序位置、重复和缺失

标准位置为pickup_1、harvest_1、return_truss、adjust、pickup_2、harvest_2、return_stem；四类标签仍是pickup/harvest/return/adjust。同一类在不同位置必须保留发生序号和任务上下文。相邻同类重复尝试记录为子事件，主四类区间不增加虚假类别转换。

只录到前三阶段、没有adjust、任务中断、回退或非常规重复时，按实际可见序列标注并打标签，不能补齐不存在的阶段。四类概率本身不能证明处于第几次pickup；该信息依赖开始位置和历史进度。

## 两人复核与修订记录

1. 每位复核者先看无模型概率/预测边界版本，独立记录可观察锚点、建议点、最早/最晚合理帧、遮挡/动作重叠、置信度及依据。历史包由错例筛选，不能称为独立盲测；网页隐藏只是减少锚定。
2. 再显示原边界和模型，`model_seen`永久记录为true。不得通过重新隐藏声称未看过模型。建议必须根据动作证据，模型时刻只用于定位问题。
3. 两位意见分歧保留两份记录，第三方裁决/共识另存，记录复核者、日期、规范版本、源标注SHA、原边界、建议点、区间和理由。不能覆盖旧意见。多个误报案例指向同一个真实事件时，也要检查意见是否冲突。
4. 已完成意见不等于批准修改标签；本轮只收集建议。若后续决定改规范，应统一审计相同语义的正确/错误样本，发布新标注版本，再做预注册的开发集对照，不能只修改失败样本后报告分数提升。
5. 独立测试的真正盲包不含模型输出、排名、错例标签和指标文件；由数据保管者封存。锁定模型/阈值/规范后一次验收。隐藏网页内容不能代替权限和盲法。

## 本地使用

人工复核包位于`runs/tomato/boundary_review_20261109/review_package`，默认页面按41条去重审查项目组织：18个真实边界和23个未匹配预警，覆盖16次漏检、全部9次adjust→pickup和提前Prompt案例。所有视频保留30Hz，图中概率仍是原始2Hz输出；不能把连线当作额外模型观测。

页面提供逐帧步进、0.25倍速、58个命名关节的实测位置/差分速度、当前/未来概率、原边界与模型边界、完整状态CSV和Prompt/Chunk日志。黑虚线为人标边界，紫色点线为原始四类模型0.5/K2变化；真实Prompt确认采用0.8/Current K2，必须查看独立日志。

意见只保存至浏览器或导出JSON，不写源标注。优先导出备份；校验命令：

```bash
.venv-tomato/bin/python -m tools.validate_tomato_boundary_reviews exported-opinions.json
```

校验只验证身份、帧范围和意见结构，不自动裁决，也不自动应用修订。
