## 五个问题的结论

1. 硬门控丢掉低风险的真实转换；不是简单的全局低估。seed42中B0命中39，B1保留32，丢7个：{'harvest->return': 2, 'return->adjust': 2, 'adjust->pickup': 2, 'pickup->harvest': 1}。两个正确adjust→pickup的风险仅0.098和0.366，都被0.5过滤。真实近事件窗口里adjust→pickup风险均值0.194，pickup→harvest/harvest→return约0.646/0.656。可是adjust全窗口平均预测0.089、真实阳性率0.071，并非总体偏低；稳定段占比可掩盖近边界的系统性漏报。

2. 时间头有辅助价值：正确预警风险均值0.711、错误0.228；候选排序AUROC0.895，AP0.961，Future置信度排序AP0.855。样本是39个匹配和13个未匹配候选，排序标签来自验证匹配；不是独立测试排序保证。只附加时间估计或排序元数据、保持时间顺序和预警集合不变，两种非硬门控方案均维持39/50和13误报（0.674/分钟）。不能把排序后丢候选称为非过滤。

3. B2额外丢掉B1命中的13次，其中{'no_expected_online_phase_in_window': 12, 'risk_future_confirmation_or_phase_timing': 1}。12例在真实允许窗口中，在线状态已经不处于应有的前一阶段，反映前序漏确认/早确认的级联；不能把这13例全部归咎于时间头单次概率。分析用真实阶段只作事后诊断，回放没有以真值重置在线阶段。

4. 优先路线A：数据版本、边界规范和避免决策卡死的机制。8例关键帧、三路池化特征、右臂7D与右手22D原始30Hz位置/速度、三头概率均保存。可见细微手指/果梗变化和局部遮挡，不足以证明没有可观测先兆；也没有池化前Token对照来证明mean pooling丢失关键信息。相机角色在元数据中未明确，不擅自把某路特征称为右腕。

5. 有理由重新训练“数据刷新对照”，没有足够证据直接更换复杂网络。服务器101=旧94剔除整包3条+新10；输入SHA全部对应已核验缓存，只有已批准的一条训练标注纠正。新增10已被测试，现在用户授权加入训练，须转为开发数据；不再称它们独立盲测。计划旧74清洁训练控制组与新增后的84训练组，保持9条开发验证、8条历史测试归属；新盲测需另录。

仅在B0正确匹配的39次预警上，条件时间估计MAE=0.286秒，固定认为还有1.5秒的参考误差=0.896秒。这是命中子集上的条件比较，不能代表全50事件时刻误差，更不能把它当作召回改善。原时间头全近边界窗口的常数风险对照另见上一轮报告。时间估计可附加到预警作为研究信息，尚不用于否决Current确认或实际Prompt切换。

## 困难转换包

每个case含traces.npz（命名关节和三路1024D池化特征）、curves.png、keyframes.png、case.json，路径见adjust_cases.json。原始B0/B1/B2没有三组不同分类概率，它们共享Current/Future，区别是时间门控和在线决策；曲线不伪造独立预测头。case记录第一次匹配成功的稳定预警；另记录最近同类预警偏差，时间上不混淆早报与有效命中。

若之后研究路线B，最小对照是同一冻结编码器、同一三路16帧输入、相同训练组与三种子，对比mean pooled readout与小型Token attention readout，并以分组开发集选参和全新录制盲测验收；先记录新增Token缓存/内存成本，不解冻大编码器。该实验本轮不执行，因为当前没有证明特征是主要瓶颈。

补录应独立覆盖：调整后停顿、重新接近、只调整不拿起、失败抓握/重复抓握、不同速度和遮挡；分别标手指闭合、物体首次持续运动、离盘锚点，再按统一阶段起点规范确定标签。不能用模型概率阈值定义真值。
