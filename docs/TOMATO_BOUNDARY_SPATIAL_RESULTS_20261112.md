# 边界监督与空间读出：实际单因素实验

2026-11-12，research-tomato-agent，起点f5c65c0。根据用户同意，先测试边界训练监督，再做小规模空间读出；Memory仍未参与决策。

## 结果

**两项实验都没有产生足够稳定的改进，不替换B0。** 所有旧模型、数据划分、原Subtask与默认Prompt/RTC均保留。

### 1. 边界强调，匹配Current-only对照

- 冻结相同V-JEPA2 4000D缓存；Current使用原4000→256→4 GELU/Dropout .3 MLP。
- C0普通类别加权CE；C1只将人工边界前后1秒窗口的训练权重乘3。类别权重与归一化均只拟合训练折。
- 两者每个种子、每个折初始化逐位相同，随机批次、30epochs、batch256、AdamW LR.0003/WD.01相同；无早停、无开发集阈值搜索。
- 84条按原始录制做5折OOF，三个种子，每方法最后再用84条固定训练一次，共36个新Current checkpoint。Future仍用原冻结1.5秒概率，阶段确认仍用Current .8/K2。
- 新Current头是研究分支，默认B0 Current没有修改。

原B0开发三种子按时131、提前8、滞后5、状态不一致119.5s；新C0为134/4/6、123s。C0相对B0有小幅时机变化，但数据与训练来源、权重均不同，不能归因于边界强调；其平均Current F1约0.9626，低于原B0约0.9692，且未在独立录制上验证。不选Seed44或开发上的单个计数替换B0。

本轮仅测试**边界权重这一因素**，没有把它称为CycleVLA完整复现或RoboMonitor时序一致性训练。Current是单个固定缓存窗口的MLP，同一时间戳反复输入完全相同特征并没有可比较的不同历史读出；不能添加无意义的“重叠一致性”损失并宣称实现论文方法。真正多上下文因果读出应单独设匹配对照。

### 2. 冻结空间Token小规模探针

固定从训练84条选12条（8条B0见过、4条未见）；围绕六次边界取−1、−.5、+.5、+1秒最近已有锚点，共288个真实16帧因果窗口。未读取开发/历史测试视频。

重新调用本地官方冻结V-JEPA2，保留三相机每路4×4空间区域特征：

- 依据本地Transformer实际Conv3D展平顺序恢复8×16×16的时空Token布局；时间维与每个4×4 patch小区求均值，得到3×16×1024。
- 原全Token均值与16区域均值数值一致性已验收；缓存保存float16，原数据不变。
- global_mean_control将每路均值广播至16区域；spatial_4x4保留区域差异。两者相同48位置、相同64D state-query注意力结构、相同参数数量与初始化、相同训练统计/预算。
- 两者都没有长期历史输入、ROI或Memory；不接人工七阶段位置。
- 12条录制做3折整录制OOF，三个种子、固定40epochs，共18个读出checkpoint。评价只针对这288个训练来源近边界样本，不计算完整Episode切换率。

|种子|均值对照 Macro-F1|4×4空间读出 Macro-F1|

|42|0.7815|0.7367|
|43|0.7926|0.7334|

|均值|0.7818|0.7384|

在这个小数据、读出方式和训练预算下没有收益，不扩大到全部100条，也不直接部署。不能与B0在完整开发时间轴上的0.97分类F1直接比较，更不能据此证明“局部视觉没有用”：4×4 coarse Token仍不同于交互ROI、细粒度物体关系或高分辨率局部图。

### 3. 资源与验证

- 边界监督主run约89.97s，36个模型；原4000D缓存复用，无编码器提取。
- 空间探针约56.99s，288次三视图编码调用＋18个小模型拟合。编码调用P50约40.76ms、P95约46.24ms、最大约173.90ms，含预处理/设备传输，不含原视频解码、读出、通信或动作执行。
- 没有收集训练进程峰值显存，不用模型大小估计冒充实测峰值。
- 36个边界模型和18个空间模型逐一核验：训练/留出录制无重叠，所有归一化统计与对应训练折重算逐位相同，匹配方法初始化一致。
- 314项番茄Python测试通过、1项跳过；Memory三类模块67项另行通过。固定B0与原标注哈希核验通过。
- 没有下载新权重，未修改OpenPI、RTC或连接真实机器人。
